# תוכנית UX וביצועים ל-Car360

מסמך עבודה: מה הבעיות, לפי איזה עקרונות פותרים אותן, מה כבר בוצע ומה הצעדים הבאים.
העדיפות לכל אורך הדרך: **שהמשתמש ימצא את עצמו מהר**, שהאפליקציה תרגיש מיידית,
ושכל פיקסל על המסך יעבוד בשביל משהו.

---

## 1. האבחנה

### 1.1 ניווט — "איפה אני ואיך מגיעים למה שרציתי"

| בעיה | למה זה כואב |
| --- | --- |
| אין חיפוש | לטיפול משנה שעברה מגיעים רק בשרשרת: בית → בחירת רכב → טיפולים → גלילה |
| ניווט לרוחב חסום | מסכי הרכב (טיפולים/ביטוח/מסמכים) נגישים רק דרך דף הבית; החלפת רכב דרשה חזרה לבית |
| חזרה שבירה | `navigate(-1)` מדף שנפתח מקישור/התראה (אין היסטוריה) הוביל לשום מקום |
| מיקום גלילה נשמר בין מסכים | מעבר למסך חדש נחת באמצע הדף |
| מסך הגדרות ארוך מאוד | סטודיו העיצוב (פלטות, שפות עיצוב, צבע דגש, זוהר) דחף את ההתראות והגיבוי מתחת לקפל |

### 1.2 עומס מידע

- **מתג פריסת דף הבית** ישב קבוע במסך הראשי: פקד שמשנים פעם בחיים תופס מקום כל יום.
- **מצב כהה** הופיע גם בכותרת הבית וגם בהגדרות.
- כרטיסי טיפול/ביטוח הציגו *"3 תמונות"* כטקסט — מידע שאי אפשר לעשות איתו כלום.
- טקסטי עזר ארוכים (הסרת רקע, מצב ענן) חזרו על מה שהמסך כבר אומר.

### 1.3 ביצועים

| מקור האיטיות | הסבר |
| --- | --- |
| חבילת JS אחת גדולה | כל המסכים (כולל דוח רכב וסטודיו העיצוב) נטענו בהפעלה הראשונה |
| קריאה חוזרת לרשת בכל ניווט | כל כניסה למסך יצרה `getDocs` מחדש — גם אם נכנסנו אליו לפני שנייה |
| תזכורות סדרתיות | `collectReminders` רץ רכב-אחרי-רכב, 3 קריאות לכל רכב, בטור |
| טשטוש כבד | `backdrop-filter: blur(22–26px)` על כל אריח + שכבות זוהר במסך מלא — ה-GPU של טלפון בינוני נחנק בגלילה |
| אין מטמון מקומי ל-Firestore | כל טעינה = רשת; אופליין = מסך ריק |

## 2. עקרונות

1. **מיידיות לפני אנימציה** — מה שכבר נטען מוצג מיד; רענון קורה ברקע בלי שלד טעינה.
2. **כל דבר במרחק חיפוש אחד** — אם יש לזה שם, אפשר להגיע אליו בהקלדה.
3. **הקשר תמיד גלוי** — באיזה רכב אני, ואיך עוברים לאחר, בלי לחזור אחורה.
4. **פקד שמשתמשים בו פעם בשנה לא חי במסך הראשי.**
5. **מידע שלא ניתן לפעול לפיו — החוצה** (או להפוך אותו לפעולה).
6. **העיצוב לא נסוג, הוא מתייעל** — אותה שפה ויזואלית בעלות חישובית נמוכה יותר.

## 3. מה בוצע (שלב 1 — הענף הזה)

### 3.1 התקלה שדווחה: אי אפשר לצפות בתמונה שהועלתה

- **`ImageViewer` חדש** — מציג תמונה במסך מלא: החלקה בין תמונות, לחיצה להגדלה ו-pan,
  מונה תמונות, הורדה, מחיקה, סגירה ב-Esc/כפתור.
- **`PhotoPicker`** — לחיצה על תמונה פותחת אותה בצופה (קודם היה אפשר רק למחוק).
- **כרטיסי טיפול וביטוח** — במקום התווית "3 תמונות" מוצגת רצועת תמונות ממוזערות;
  לחיצה פותחת את הצופה ישירות, בלי לפתוח את טופס העריכה.
- **מסך המסמכים** — הצפייה עברה מגיליון תחתון לצופה המלא, עם מעבר בהחלקה בין כל
  המסמכים המסוננים.
- תוקנה גם בעיית HTML: כפתור/קישור בתוך כפתור (הכרטיסים היו `<button>` עוטף).

### 3.2 ניווט

- **חיפוש מהיר גלובלי** (`GlobalSearch`) — רכבים, טיפולים, ביטוחים, מסמכים, תזכורות
  **וגם מסכי האפליקציה**. נפתח מכפתור בכותרת כל מסך ומדף הבית; Enter קופץ לתוצאה
  הראשונה; בחירה מחליפה גם את הרכב הפעיל.
- **מחליף רכבים בכותרת** — בכל מסך של רכב, שם הרכב הוא כפתור: בחירה מעבירה לאותו
  מסך של הרכב האחר.
- **חזרה חכמה** — אם אין היסטוריה (קישור עמוק, התראה, פתיחת PWA) הכפתור מוביל לדף הבית.
- **`ScrollRestoration`** — מסך חדש מתחיל מלמעלה, וחזרה מחזירה למקום שבו היינו.
- **"עיצוב ותצוגה" הפך למסך משלו** (`/settings/design`) — ההגדרות התקצרו לרשימה קריאה.

### 3.3 פחות רעש

- מתג פריסת דף הבית ירד מהמסך הראשי ועבר ל"עיצוב ותצוגה".
- כפתור מצב כהה בכותרת הבית הוחלף בחיפוש (מצב כהה נשאר בהגדרות ובמסך העיצוב).
- תוויות "N תמונות/מסמכים" הוחלפו בתמונות עצמן.
- טקסטי עזר קוצרו (הסרת רקע, תאריך טסט, סטטוס ענן).
- באריח מסמכים של רכב ללא מסמכים מופיע עכשיו כפתור הוספה (קודם לא היה כלום).

### 3.4 ביצועים

- **פיצול קוד לפי מסך** — רק דף הבית והכניסה נטענים בהפעלה; כל השאר בדרישה.
  (`VehicleReportPage`, `SettingsPage`, `DesignPage`, `PassportPage` ועוד יצאו מהחבילה הראשית.)
- **מטמון משותף (`src/data/store.ts`)** בסגנון stale-while-revalidate: מסך שכבר
  נטען נפתח מיידית מהמטמון ומתרענן ברקע; בקשות זהות מתאחדות; ניקוי מלא ביציאה מהחשבון.
- **`collectReminders` במקביל** — כל הרכבים וכל הקולקציות יחד, ודרך המטמון.
- **מטמון מקומי ל-Firestore** (`persistentLocalCache` + ריבוי טאבים) — קריאות חוזרות
  מהמכשיר, עבודה אופליין.
- **עלות ציור נמוכה יותר** — רדיוסי הטשטוש ירדו (22–26px → 12–16px), הזוהר הסביבתי קטן,
  ושכבות הרקע המונפשות נכבות ב-`prefers-reduced-motion`.
- **"מצב מהיר"** (הגדרות → עיצוב ותצוגה) — מכבה טשטוש וזוהר לחלוטין לטלפונים חלשים.
  ההעדפה נשמרת פר-מכשיר ולא מסתנכרנת לענן.
- `touch-action: manipulation` — ביטול השהיית 300ms בכל לחיצה.
- `loading="lazy"` + `decoding="async"` בכל התמונות הממוזערות.

## 4. הצעדים הבאים

### שלב 2 — מהירות נתפסת (קצר)

1. **שמירה אופטימית**: הכרטיס מופיע ברשימה מיד, וההעלאה לרשת קורית ברקע (היום
   ממתינים לענן לפני שהגיליון נסגר).
2. **העלאת תמונות ברקע** עם תור וניסיון חוזר — כרגע שמירת טיפול עם 3 תמונות ממתינה
   ל-3 העלאות סדרתיות.
3. **תמונות ממוזערות אמיתיות**: לשמור `thumb` (פרופיל קיים ב-`lib/images.ts`) לצד
   התמונה המלאה, ולהציג אותו ברשימות — היום כל רצועת תמונות מורידה תמונות מלאות.
4. **`prefetch` של מסך בלחיצה ארוכה/hover** על אריחי דף הבית.

### שלב 3 — ניווט מתקדם

1. **מסך רכב אחד (Car Hub)** שמאחד טיפולים/ביטוח/מסמכים/תזכורות בלשוניות, במקום
   ארבעה מסכים נפרדים עם אותה כותרת.
2. **מיון וסינון ברשימות** (לפי תאריך/עלות/מוסך) + סיכום שנתי בראש מסך הטיפולים.
3. **פעולות מהירות בהחלקה** על כרטיס (מחיקה/עריכה/שכפול).
4. **היסטוריית חיפוש ותוצאות אחרונות** בפתיחת החיפוש.
5. **קיצור מקלדת `/`** לפתיחת חיפוש בדסקטופ.

### שלב 4 — איכות ונגישות

1. מעבר על ניגודיות (`text-ink-3` על רקע זכוכית בהיר גבולי ב-4.5:1).
2. מיקוד מקלדת גלוי בכל הפקדים (טבעות מיקוד אחידות).
3. `aria-live` להודעות Toast, ותיאורי מצב לצופה התמונות.
4. בדיקות Playwright קבועות למסלולים: הוספת רכב → טיפול עם תמונה → צפייה → חיפוש.
